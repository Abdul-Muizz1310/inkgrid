# M4 Verify Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grade a `Document` against its PDF with a second engine: every character PDFium reads is
owned by exactly one word that holds it, every table's cells hold the ink inside them, and every
value is bound to one block and one cell, reported as a typed `VerificationReport`.

**Architecture:** `verify/pdfium_reader.py` (the only pypdfium2 importer) turns the PDF into the
verifier's own page model (`verify/ink.py`): characters with loose boxes and kinds, and rules from
path geometry with its own thresholds (`verify/rules.py`). Three pure modules grade the document:
`verify/ownership.py` (characters to words; LOST, DOUBLED, INVENTED), `verify/checks.py` (the table
checks and value fidelity), and `verify/report.py` (page statuses and assembly). The report type is
in `model/verification.py`, so the inspector can draw it. `api.verify` is the shell; `inkgrid verify`
and the inspector's overlays sit on top.

**Tech Stack:** Python 3.12+, uv, pytest 9, Hypothesis, Ruff, mypy `--strict`; pypdfium2 5.13.0
(PDFium 153.0.7999.0) becomes a direct dependency (already locked through Camelot).

**Spec:** `docs/specs/10-verify.md`

## Global Constraints

- Spec-TDD: every case is a test named `test_<CaseId>_<slug>`, written and watched failing before code.
- Layer table: `verify` imports only `model` and pypdfium2, and only `verify/pdfium_reader.py`
  imports pypdfium2; `render` imports only `model` and `read`; `api` is the only module that joins
  `read` and `verify`.
- Never loosen a check to make a document pass: a benign case is classified and counted; the check
  stays as strict as the spec states it.
- Constants exactly as spec 10: `SLANT_MAX = 1.0`, `MIN_LENGTH = 3.0`, `THIN_MAX = 3.0`,
  `MERGE_AT = 0.5`, `MERGE_GAP = 1.0`, `CROSS_MARGIN = 1.0`, `EDGE = 2.0`, `FRAME_TOL = 0.5`; line
  overlap more than half the smaller height; placement a strict majority.
- ASCII-only source: non-ASCII test data as `\uXXXX` escapes.
- Corpus runs are sequential, one document at a time, niced.
- Commits: Conventional Commits, imperative, at most 72 characters, no emoji, no `Co-Authored-By`.

## Review Focus

1. **A clip path on text inside a Form XObject.** PDFium's clip-path coordinates may not be page
   space there. Expected: a misclassified clipped character is never silently benign; the page's
   `clipped_chars` bounds the class (§ 3.2), so an excess turns into LOST. Task 5 pins the bound
   (DC6 and DC7 at count 0).
2. **Degenerate word boxes** (a zero-width glyph, a word of combining marks). Expected: the word still
   owns its character (OW5, Task 5).
3. **A document whose page count differs from PDFium's** with an equal SHA-256 (a truncated
   reading). Expected: pages beyond are LOST or declared; pages PDFium lacks are UNVERIFIED (DC9,
   DC10, Task 7).
4. **Non-ASCII text in defects** (`€`, U+FFFD) in the JSON report and the inspector. Expected: the
   report round-trips and the inspector escapes it (RP6, Task 7; VI4, Task 8).
5. **Pages with many characters.** Expected: ownership and table checks index by band, never pairwise
   over the page: Cboe's 24 pages verify in under 5 s. Task 10 records the corpus timing.
