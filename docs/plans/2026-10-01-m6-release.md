# M6 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 0.1.0 on PyPI: a version tag publishes through Trusted Publishing with attestations.

**Architecture:** a stdlib release check (`scripts/check_release.py`) refuses a tag that must not
publish; `release.yml` runs it, the CI gates, and one build, then publishes the same files to TestPyPI
and PyPI from two OIDC-only jobs. The version bump and changelog section are the last commit, after
M5 merges.

**Tech Stack:** GitHub Actions, `pypa/gh-action-pypi-publish` v1.14.2, uv 0.12.19.

**Spec:** `docs/specs/17-release.md`

## Global Constraints

- No tag is pushed before the user confirms both pending trusted publishers (spec 17 § 5).
- Every action pinned by its full commit SHA with a version comment; `permissions: {}` at the top.
- No secret, token, or password in any workflow.
- The look-back corpus runs one document at a time, never beside another corpus job.
- Conventional Commits, a subject of at most 72 characters, no trailer.

## Review Focus

1. **Template injection:** the tag reaching a `run:` script through `${{ }}` rather than an env var.
2. **A publish job running repository code** while it holds `id-token: write`.
3. **A rerun after a failed PyPI upload** blocked by TestPyPI refusing a file it already has.
4. **A dev version or an undated changelog** published because the check passed on a malformed file.
5. **README claims** left at M4's look-back numbers after M5c changed the reading.
